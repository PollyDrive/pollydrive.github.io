Архитектура харнеса и основные функциональные блоки

Харнес построен на базе React Agent, выполняет цикл вызова инструментов и принятия решений о следующем шаге или ответе.

Четыре ключевых инструмента (тулы), которые есть у всех харнесов:

| Инструмент | Описание |
| ---- | ---- | ---- |
| Чтение файла | Получение данных из файлов |
| Поиск среди файлов | Поиск информации в файловой системе |
| Редактирование файла | Изменение содержимого файлов |
| Bash-команды | Выполнение консольных команд |
Проблема: длинные сложные задачи (например, создание игры с множеством концовок) не помещаются в контекст агента и невозможны к решению одним проходом.

- Решение: запуск харнеса внутри бесконечного цикла shell (bash while true), где агент постепенно улучшает результат, завершает задачу, и цикл перезапускает его, чтобы продолжить работу.
- Такой подход позволяет агенту работать неограниченно долго (напр., неделю), улучшая результат шаг за шагом.
- Объяснение: у модели существует «умный» участок контекста (~30-40%), после которого качество начинает падать — данный метод позволяет оставаться в пределах этого оптимального контекста.

Например Pi

- **Радикальный минимализм (YAGNI):** В отличие от многофункциональных платформ вроде Cursor или Claude Code, Pi не содержит огромного количества встроенных скиллов. Он предоставляет модели только базовый, низкоуровневый доступ к операционной системе — инструменты для чтения (Read) и записи (Write) файлов.
- **Саморасширяемость:** Базовая концепция харнесса заключается в том, что если агенту нужен новый инструмент или плагин для решения задачи, он не скачивает его, а пишет код этого инструмента самостоятельно.
- **Изоляция и управление контекстом (Memory):** Pi управляет краткосрочной памятью агента. Он сохраняет диалоги и вызовы инструментов в виде древовидных структур (JSONL). Это позволяет делать форки (ответвления) от любой точки диалога для параллельных экспериментов без загрязнения основного контекста.

**Итог:** Если LangChain — это тяжеловесный фреймворк с сотнями готовых коннекторов и цепочек для сборки LLM-приложений, то Pi — это утилитарная "оболочка", которая дает модели доступ к терминалу и файловой системе, оставляя реализацию всей остальной логики самой модели.
